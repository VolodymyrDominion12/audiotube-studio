# AudioTube Studio — концепція

> Локальний застосунок, який перетворює AI-аудіорозбори (~20 хв на тему) на готові YouTube-відео з тематичним візуалом, метаданими, субтитрами й автоматичним розкладанням по плейлистах.

Версія документа: 0.1 · Дата: 2026-10-21 · Статус: чернетка концепції

---

## 1. Мета і контекст

**Що є:** набір корисних аудіофайлів — AI-згенеровані розбори тем («за 20 хвилин зрозуміти концепцію X»).

**Що потрібно:** без ручного монтажу перетворювати кожне аудіо на YouTube-відео і публікувати його в потрібний плейлист.

**Принципи:**
- **Локально** — рендер, транскрибування і (за бажанням) генерація зображень працюють на власному комп'ютері; зовнішні API — опційні.
- **Конвеєр «кинув файл — отримав відео»** — мінімум ручних дій, але з можливістю переглянути й поправити перед публікацією.
- **Від простого до складного** — MVP: картинка + аудіо. Далі: зациклене відео, тематичні слайди, генерація зображень.
- **Ідемпотентність** — кожен крок зберігає результат; повторний запуск не робить зайвої роботи і не дублює завантаження на YouTube.

## 2. Користувацький сценарій

1. Користувач кладе `docker_basics.mp3` у папку `inbox/` (або обирає файл у GUI).
2. Застосунок:
   1. транскрибує аудіо (текст + таймкоди);
   2. через LLM визначає тему, генерує **назву, опис, теги, розділи (chapters)**, ключові слова для візуалу і пропонує **плейлист** (напр. «DevOps за 20 хвилин»);
   3. підбирає або генерує візуал (за обраним режимом);
   4. рендерить відео 1080p (+ обкладинку/thumbnail, + файл субтитрів `.srt`);
   5. показує результат на перевірку (або пропускає цей крок в авто-режимі);
   6. завантажує на YouTube, додає субтитри, обкладинку, кладе у плейлист (створює плейлист, якщо його ще немає).
3. Статус кожного відео видно в таблиці: `new → transcribed → described → visuals → rendered → approved → uploaded → in_playlist`.

## 3. Режими візуалу

| # | Режим | Як виглядає | Складність | Для MVP |
|---|-------|-------------|-----------|---------|
| A | **Статична картинка** | Одне тематичне зображення + повільний zoom/pan (ефект Ken Burns), назва теми | Низька | ✅ |
| B | **Зациклене фонове відео** | Короткий кліп 10–30 с (рідина, космос, абстракція, природа) повторюється всю тривалість | Низька | ✅ |
| C | **Аудіовізуалізатор** | Хвиля/спектр поверх фону (A або B) — додає «живості» | Середня | Фаза 2 |
| D | **Тематичне слайдшоу** | Окреме зображення на кожен розділ (chapter) з плавними переходами + заголовок розділу | Середня | Фаза 2 |
| E | **AI-генерація зображень** | Картинки генеруються за промптами з транскрипту (стиль задається пресетом) | Висока | Фаза 3 |
| F | **Субтитри на екрані** | Вшиті субтитри або «ключова фраза розділу» великим шрифтом | Середня | Фаза 2 |

Режими комбінуються: наприклад, **B + C + F** (зациклений космос + хвиля + субтитри).

**Бібліотека фонів:** локальна папка `assets/loops/` з категоріями (`space/`, `fluid/`, `abstract/`, `nature/`, `tech/`). LLM за темою обирає категорію; наприклад, тема про астрофізику → `space`, про фінанси → `abstract`.

## 4. Джерела візуалу

| Джерело | Тип | Вартість | Примітка |
|---------|-----|---------|----------|
| Власна бібліотека `assets/` | фото, відеолупи | безкоштовно | найнадійніше з погляду авторських прав |
| **Pexels API** | фото + відео | безкоштовно, з ключем | ліцензія дозволяє комерційне використання |
| **Pixabay API** | фото + відео | безкоштовно, з ключем | аналогічно |
| **Unsplash API** | фото | безкоштовно, з ключем | вимагає атрибуції через API |
| **Локальний Stable Diffusion / FLUX** (diffusers або ComfyUI) | генерація зображень | безкоштовно, потрібна GPU (≥8 ГБ VRAM) | повний контроль стилю |
| Хмарні генератори (OpenAI Images, Replicate тощо) | генерація | платно за картинку | якщо немає потужної GPU |
| Процедурна генерація (шейдери, шум Перліна, частинки) | абстрактне відео | безкоштовно | можна рендерити унікальні лупи самостійно |

Кожне використане зображення записується в `manifest.json` проєкту відео з джерелом і ліцензією — щоб за потреби додати атрибуцію в опис.

### 5.1 Модулі

**Transcriber** — `faster-whisper` (локально, підтримує українську). Вихід: `transcript.json` (сегменти з таймкодами) + `subtitles.srt`.

**Content Planner (LLM)** — з транскрипту генерує:
- назву (до 100 символів, з «гачком»), опис (з таймкодами розділів), теги;
- розділи (chapters) — 5–10 штук з таймкодами;
- плейлист (вибір з існуючих або пропозиція нового);
- візуальні ключові слова / промпти для генерації по кожному розділу;
- текст для обкладинки (2–4 слова).

Провайдер LLM — змінний: **Ollama** (локально, напр. Qwen / Llama) або **Claude API** / інший хмарний. Вихід валідується через Pydantic-схему.

**Visuals Provider** — спільний інтерфейс `get_visuals(plan, mode) -> list[Asset]` з реалізаціями: `LocalLibrary`, `PexelsProvider`, `PixabayProvider`, `SDGenerator`, `ProceduralLoop`. Кешує завантажене в `cache/`.

**Renderer** — FFmpeg напряму (швидше і стабільніше за MoviePy для 20-хвилинних відео):
- статична картинка: `-loop 1 -i bg.jpg -i audio.mp3 -tune stillimage -shortest`;
- зациклене відео: `-stream_loop -1 -i loop.mp4 -i audio.mp3 -shortest`;
- zoom/pan: фільтр `zoompan`; хвиля: `showwaves` / `showfreqs`; текст: `drawtext`; субтитри: `subtitles=`;
- апаратне кодування NVENC/VAAPI, якщо доступне;
- окремо генерує thumbnail 1280×720 (Pillow: фон + великий текст).

**YouTube Publisher** — YouTube Data API v3 через `google-api-python-client`, OAuth 2.0 (токен зберігається локально):
- `videos.insert` — завантаження (resumable upload);
- `thumbnails.set` — обкладинка;
- `captions.insert` — субтитри `.srt`;
- `playlists.list` / `playlists.insert` — пошук або створення плейлиста;
- `playlistItems.insert` — додавання відео в плейлист;
- відкладена публікація через `status.publishAt` (розклад, напр. щодня о 18:00).

**Orchestrator** — запускає кроки по черзі, зберігає статус у SQLite, при збої продовжує з останнього успішного кроку. Можливий режим «watch folder»: стежить за `inbox/` і обробляє нові файли.

### 5.3 Приклад конфігурації

```yaml
channel:
  default_language: uk
  default_privacy: private        # private | unlisted | public
  schedule: "18:00"               # час відкладеної публікації
  made_for_kids: false

render:
  resolution: 1920x1080
  fps: 30
  encoder: auto                   # auto | libx264 | h264_nvenc
  preset: "space_minimal"         # файл з presets/

visuals:
  mode: loop                      # image | loop | slideshow | generated
  providers: [local, pexels]
  generator: none                 # none | sd_local | api

llm:
  provider: ollama                # ollama | anthropic | openai
  model: qwen2.5:14b

playlists:
  auto_assign: true
  auto_create: true
```

## 7. Важливі обмеження YouTube (перевірити перед стартом)

1. **Квота API.** За замовчуванням ~10 000 одиниць на день на проєкт Google Cloud. Завантаження відео — найдорожча операція (історично ~1 600 одиниць), тобто приблизно **5–6 відео на день**. Плейлисти/обкладинки коштують мало. Актуальні значення — у документації YouTube Data API. Застосунок має вести облік квоти і переносити завантаження на наступний день.
2. **Неверифікований API-проєкт.** Відео, завантажені через API-проєкт, який не пройшов аудит Google, автоматично стають **приватними** і не можуть бути опубліковані. Потрібно подати проєкт на аудит (форма YouTube API Services Audit) або публікувати вручну в YouTube Studio. Це варто вирішити якомога раніше.
3. **Розкриття AI-контенту.** YouTube вимагає позначати реалістичний синтетичний контент. В API є поле `status.containsSyntheticMedia` — для AI-озвучення варто виставляти його свідомо (налаштування в конфігурації).
4. **Монетизація.** Політика YouTube щодо «неоригінального / масово створеного» контенту (inauthentic content) може обмежити монетизацію каналу, де відео виглядають однаково і зроблені за шаблоном. Що допомагає: унікальний візуал під кожну тему (режими D/E), розділи, субтитри, якісні описи, різні обкладинки.
5. **Авторські права на візуал і музику** — використовувати лише власні, згенеровані або ліцензовані (Pexels/Pixabay) матеріали; фоновою музикою не перекривати голос.

## 8. План розробки

### Фаза 1 — MVP (1–2 тижні)
- [ ] Каркас проєкту, конфіг, CLI.

### Фаза 4 — Канал як система
- [ ] Розклад публікацій, watch-folder, облік квоти.
- [ ] Shorts: автоматичне нарізання 30–60 с найцікавіших фрагментів (вертикальний формат).

- [ ] Багатомовність: переклад назви/опису/субтитрів.

## 9. Відкриті питання

1. Яка GPU на комп'ютері? Від цього залежить, чи реальна локальна генерація зображень і NVENC-рендер.
2. Мова контенту — лише українська чи ще й англійська (окремий канал / мультимовні метадані)?
3. Чи генеруються аудіо автоматично (напр. з NotebookLM-подібного інструмента)? Якщо так — можна під'єднати й цей крок до конвеєра.
4. Скільки відео на тиждень планується публікувати? (впливає на квоту та розклад)
5. Повна автоматика чи обов'язкова ручна перевірка перед публікацією?
6. Чи потрібні вшиті субтитри на екрані, чи достатньо субтитрів YouTube?
