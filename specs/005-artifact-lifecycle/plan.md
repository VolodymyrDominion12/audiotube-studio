# 005 · План реалізації (попередній)

**Спека:** [spec.md](spec.md) — implemented. Виходимо з того, що перегенерація дає **новий** `artifact_id`.

## 1. Підхід

1. **Missing-детекція** — після `api.audio(nb.id)` порівнюємо множину отриманих id з
   `SELECT id FROM artifacts WHERE notebook_id=?`. Різниця → `missing`; перетин з `missing` → `downloaded`.
   Для ноутбуків, яких немає у `api.notebooks()`, — усі їхні артефакти `missing`. Робимо це лише
   без фільтра `--notebook` (інакше «не прийшов» означає «відфільтрований»).
2. **Безпечний `--force`** — `_one()` при наявному файлі качає в `.part`, рахує sha256, порівнює з
   `artifacts.sha256`; `.part` видаляється в обох випадках; розбіжність → `changed` у звіті.
3. **Оновлення назв ноутбуків** — уже працює (`save_notebook` upsert, slug з БД); лише додаємо тест.

Відкинуто: періодичне перекачування для перевірки хешу — подвоює трафік і ризик блокування (конституція VI).

## 3. Дані

Міграцій не треба: колонка `state` уже є.

## 4. Ризики й відкат

Хибне `missing` через тимчасово неповну відповідь API → `missing` лише інформаційний і ні на що
не впливає, тому хибне спрацювання безпечне.
