# 006 · Ноутбук → плейлист

**Статус:** draft (відкладено рішенням від 19.11.2026) · **Версія:** 0.1 · **Дата:** 2026-11-21
**Залежить від:** 001, 003 · **Модулі:** `youtube.py`, `pipeline.py`, `db.py`, `config.py`

## 1. Проблема

Структура «папка = ноутбук» є на диску, але не на YouTube: глядач не бачить серій. Зараз
плейлист визначає LLM або YAML, а при `manage_playlists: false` — ніхто.

## 2. User stories

- **US1** Як автор, я хочу, щоб кожен ноутбук став плейлистом з тією ж назвою.
- **US2** Як автор, я хочу злити кілька ноутбуків в один плейлист через конфіг.
- **US3** Як автор, я хочу розкласти вже опубліковані відео по плейлистах однією командою.

## 3. Поза межами

Перейменування плейлистів при перейменуванні ноутбука; порядок відео в плейлисті, відмінний від порядку додавання.

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| PL-R1 | Новий режим `youtube.playlist_source: notebook | meta | none` (дефолт `meta` = поточна поведінка). |
| PL-R2 | У режимі `notebook` плейлист для задачі = `notebooks.title` через ланцюг `jobs → artifacts → notebooks`; задачі без ноутбука (ручний import) — `meta`. |
| PL-R3 | `youtube.playlist_map: {notebook_id: "Назва плейлиста"}` перекриває назву. |
| PL-R4 | Зв'язок ноутбук → `playlist_id` кешується в БД (`notebooks.playlist_id`), щоб не шукати плейлист за назвою щоразу (економія квоти). |
| PL-R5 | `audiotube playlists --backfill [--dry-run]` додає в плейлисти вже `done`-відео, яких там немає, з урахуванням квоти. |
| PL-R6 | Вартість плейлиста врахована в `estimate_upload_cost` (вже так при `manage_playlists: true`). |

## 7. Критерії приймання

| ID | Given / When / Then | Тест |
|----|---------------------|------|
| PL-AC1 | **Given** `playlist_source: notebook` **When** publish **Then** відео в плейлисті з назвою ноутбука | новий |
