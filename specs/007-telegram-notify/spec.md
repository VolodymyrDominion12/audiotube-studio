# 007 · Сповіщення в Telegram

**Статус:** draft · **Версія:** 0.1 · **Дата:** 2026-11-21
**Залежить від:** 004 · **Модулі:** `daemon.py`, новий `notify.py`, `config.py`

## 1. Проблема

Демон працює у фоні; про публікації та збої зараз можна дізнатися лише з `journalctl` або
`notify-send` (тільки якщо сидиш за цим комп'ютером). Прострочена сесія NotebookLM чи OAuth
YouTube може тихо зупинити конвеєр на дні.

## 2. User stories

- **US1** Як автор, я хочу отримати в Telegram посилання на кожне опубліковане відео.
- **US2** Як автор, я хочу одразу дізнатися, що протухла автентифікація (NotebookLM / YouTube).
- **US3** Як автор, я хочу коротке денне зведення: скачано, опубліковано, у черзі, помилки.

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| NTF-R1 | `daemon.notify` приймає `false | desktop | telegram` (`true` = `desktop` для сумісності). |
| NTF-R2 | Токен бота й chat_id — лише зі змінних середовища (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`), не з `config.yaml`. |
| NTF-R3 | Події: `published` (назва + URL), `failed_final` (задача досягла `max_attempts`), `auth_expired` (NotebookLM/YouTube), `daily_summary` (раз на добу в `summary_hour`). |
| NTF-R4 | `auth_expired` надсилається не частіше ніж раз на 12 год (без спаму кожен цикл). |
| NTF-R5 | Помилка відправки ніколи не валить цикл демона; таймаут ≤ 10 с. |
| NTF-R6 | `audiotube notify --test` надсилає тестове повідомлення. |

## 7. Критерії приймання

| ID | Given / When / Then | Тест |
|----|---------------------|------|
| NTF-AC1 | **Given** `notify: telegram` **When** публікація **Then** 1 повідомлення з URL (HTTP замокано) | новий |
| NTF-AC2 | **Given** Telegram недоступний **Then** цикл завершується успішно | новий |
| NTF-AC3 | **Given** auth протухла 3 цикли поспіль **Then** 1 повідомлення | новий |
| NTF-AC4 | **Given** немає env-змінних **Then** `doctor` попереджає, демон працює без сповіщень | новий |

## 8. Відповідність конституції

VII — HTTP мокається; VIII — секрети лише з env; без нових залежностей (stdlib `urllib`).
