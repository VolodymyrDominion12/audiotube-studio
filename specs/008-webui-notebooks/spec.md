# 008 · Вкладка «Ноутбуки» у веб-UI

**Статус:** implemented · **Версія:** 0.2 · **Дата:** 2026-11-21
**Залежить від:** 001, 004, 005 · **Модулі:** `webui.py`, `db.py`

## 1. Проблема

Щоб зрозуміти, що з NotebookLM уже скачано, що в черзі, а що на YouTube, треба комбінувати
`sync --dry-run`, `status` і YouTube Studio. Потрібен один екран «ноутбук → переказ → відео».

## 2. User stories

- **US1** Як автор, я хочу бачити список ноутбуків з лічильниками: скачано / у черзі / опубліковано / помилки.
- **US2** Як автор, я хочу розгорнути ноутбук і бачити кожен переказ зі статусом задачі й посиланням на YouTube.
- **US3** Як автор, я хочу запустити `sync` (спершу dry-run) кнопкою з UI.
- **US4** Як автор, я хочу бачити стан демона: опубліковано сьогодні / бюджет, залишок квоти, наступне вікно.

## 3. Поза межами

Редагування метаданих (вже є в поточному UI); автентифікація користувачів (UI слухає лише 127.0.0.1);
блокування ручних дій над задачами (рендер/публікація з UI) замком демона.

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| WEB-R1 | Сторінка `/notebooks` (дані — `GET /api/notebooks`): таблиця ноутбуків з лічильниками з `artifacts LEFT JOIN jobs` (див. §5). |
| WEB-R2 | `/notebooks/<id>` (дані — `GET /api/notebooks/<id>`): перекази, стан артефакту, статус задачі, тривалість, `video_id` → посилання, помилка (перший рядок). Невідомий id → 404. |
| WEB-R3 | Кнопка «Синк (план)» → `POST /api/sync?dry_run=1` → `SyncService.run(dry_run=True)`, показ плану; «Синк» → `POST /api/sync` — справжній запуск з `max_per_run`. |
| WEB-R4 | Справжній синк з UI бере той самий `data/daemon.lock`, що й демон; при зайнятому замку — 409 і повідомлення, а не паралельний запуск. Dry-run замка не бере (як і `daemon --dry-run`). |
| WEB-R5 | Панель демона (`GET /api/daemon`): `uploads_count()` / `videos_per_day`, `quota.remaining()` / ліміт, час наступного дозволеного upload, чи працює демон зараз (замок зайнятий). |
| WEB-R6 | Усі дії, що змінюють стан, — лише POST/PUT; GET нічого не змінює в БД. |

## 5. Лічильники ноутбука

Для кожного артефакту ноутбука (рядок `artifacts`) з прив'язаною задачею `jobs` (через `job_id`):

| Лічильник | Умова |
|-----------|-------|
| скачано | усі артефакти ноутбука |
| зникли | `artifacts.state = 'missing'` |
| опубліковано | `jobs.video_id IS NOT NULL` |
| помилки | не опубліковано і `jobs.error IS NOT NULL` |
| у черзі | не опубліковано, без помилки (зокрема артефакт ще без задачі) |

Час наступного upload: якщо сьогодні є публікації — `last_upload_at + min_hours_between`, інакше «зараз»;
якщо денний бюджет вичерпано — «завтра».
