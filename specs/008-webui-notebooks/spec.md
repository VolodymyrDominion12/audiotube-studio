# 008 · Вкладка «Ноутбуки» у веб-UI

**Статус:** draft · **Версія:** 0.1 · **Дата:** 2026-11-21
**Залежить від:** 001, 004 (бажано 005) · **Модулі:** `webui.py`

## 1. Проблема

Щоб зрозуміти, що з NotebookLM уже скачано, що в черзі, а що на YouTube, треба комбінувати
`sync --dry-run`, `status` і YouTube Studio. Потрібен один екран «ноутбук → переказ → відео».

## 2. User stories

- **US1** Як автор, я хочу бачити список ноутбуків з лічильниками: скачано / у черзі / опубліковано / помилки.
- **US2** Як автор, я хочу розгорнути ноутбук і бачити кожен переказ зі статусом задачі й посиланням на YouTube.
- **US3** Як автор, я хочу запустити `sync` (спершу dry-run) кнопкою з UI.
- **US4** Як автор, я хочу бачити стан демона: опубліковано сьогодні / бюджет, залишок квоти, наступне вікно.

## 3. Поза межами

Редагування метаданих (вже є в поточному UI); автентифікація користувачів (UI слухає лише 127.0.0.1).

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| WEB-R1 | Сторінка `/notebooks`: таблиця ноутбуків з лічильниками з `artifacts JOIN jobs`. |
| WEB-R2 | `/notebooks/<id>`: перекази, статус задачі, тривалість, `video_id` → посилання, помилка (перший рядок). |
| WEB-R3 | Кнопка «Синк (план)» → `SyncService.run(dry_run=True)`, показ плану; «Синк» — справжній запуск з `max_per_run`. |
| WEB-R4 | Запуск синку з UI бере той самий `flock`, що й демон; при зайнятому замку — повідомлення, а не паралельний запуск. |
| WEB-R5 | Панель демона: `uploads_count()` / `videos_per_day`, `quota.remaining()`, час наступного дозволеного upload. |
| WEB-R6 | Усі дії, що змінюють стан, — лише POST. |

## 7. Критерії приймання

| ID | Given / When / Then | Тест |
|----|---------------------|------|
| WEB-AC1 | **Given** БД з 2 ноутбуками **When** GET `/notebooks` **Then** обидва з правильними лічильниками | новий |
| WEB-AC2 | **When** POST синк-план **Then** БД не змінена | новий |
| WEB-AC3 | **Given** замок зайнятий **When** POST синк **Then** 409 і повідомлення | новий |
| WEB-AC4 | GET-запити нічого не змінюють | новий |
