# 009 · Поділ субтитрів за часом і швидкістю читання

**Статус:** approved · **Версія:** 0.2 · **Дата:** 2026-11-21
**Залежить від:** 002 · **Модулі:** `transcript.py`, `config.py`, `transcribe.py`, `pipeline.py`, `cli.py`

## 1. Проблема

`build_cues` ділить сегмент Whisper лише за довжиною рядка (`max_chars`) і кількістю рядків (`max_lines`).
Через це довгий сегмент (з VAD це буває 15–30 с) з коротким текстом висить на екрані одним титром
усі ці секунди, а щільний текст змінюється швидше, ніж його можна прочитати. Межі титрів падають
на випадкове слово посеред фрази, а рядки виходять нерівні («довгий рядок / одне слово»). Від цих
субтитрів залежать і вшиті титри (`burn_subtitles`), і доріжка на YouTube (`upload_captions`).

## 2. User stories

- **US1** Як глядач, я хочу, щоб жоден титр не висів на екрані надто довго і не зникав раніше, ніж я його прочитаю.
- **US2** Як глядач, я хочу, щоб титр закінчувався на межі речення чи фрази, а не посеред думки.
- **US3** Як автор, я хочу налаштувати ліміти в `config.yaml`, не чіпаючи код.
- **US4** Як автор, я хочу перебудувати субтитри вже транскрибованих аудіо за новими правилами без повторної транскрипції.

## 3. Поза межами

Стилі й позиція вшитих титрів, переклад, караоке-підсвітка слів, редагування SRT у веб-UI.
Таймкоди слів від Whisper (`word_timestamps`) — окрема майбутня спека (§9). Оновлення доріжки субтитрів
на YouTube для вже опублікованих відео — не робимо (§9).

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| SUB-R1 | Тривалість титра ≤ `max_cue_seconds` (типово 7.0 с). Сегмент, що довший за ліміт, ділиться на кілька титрів, навіть якщо текст уміщається у `max_lines` рядків. |
| SUB-R2 | Тривалість титра ≥ `min_cue_seconds` (типово 1.0 с; зараз жорстко 0.8), якщо це не призводить до накладання на наступний титр. |
| SUB-R3 | Швидкість читання ≤ `max_cps` символів/с (типово 17, пробіли не рахуються). Якщо титр «щільний», його кінець подовжується в тишу після нього, але не далі за наступний титр і не понад `max_cue_seconds`. Якщо тиші не вистачає, титр лишається як є; кількість таких титрів пишеться в журнал `transcribe`. Останній титр подовжується не далі за `duration` транскрипту. |
| SUB-R4 | Точки поділу тексту за пріоритетом: кінець речення (`. ! ? …`), потім межа фрази (`, ; : —`), потім будь-який пробіл. Слово рветься лише тоді, коли воно саме довше за `max_chars` (як зараз). |
| SUB-R5 | У дворядковому титрі рядки збалансовані: різниця довжин мінімальна серед допустимих розривів. Розрив на розділовому знаку має перевагу, якщо він погіршує баланс не більше ніж на 30 %. |
| SUB-R6 | Титри впорядковані й не накладаються. Паузу між сусідніми титрами коротшу за 0.3 с закриваємо, подовжуючи попередній титр (менше мерехтіння). |
| SUB-R7 | Титр ніколи не починається раніше за початок свого сегмента, а час усередині сегмента розподіляється пропорційно кількості символів (як зараз). |
| SUB-R8 | Той самий `transcript.json` і ті самі налаштування дають побайтово однаковий SRT. |
| SUB-R9 | Обмеження `max_chars` і `max_lines` діють, як і раніше: жоден рядок не довший за `max_chars`, жоден титр не має більше `max_lines` рядків. |
| SUB-R10 | Нові правила діють скрізь, де генерується SRT: `transcribe`, автогенерація перед рендером/публікацією та команда `subtitles`. |
| SUB-R11 | `audiotube subtitles [id ...]` будує `workspace/<slug>/subtitles.srt` з наявного `transcript.json` без транскрипції. Без id — усі задачі з транскриптом. Без `--force` — лише там, де SRT ще немає (ідемпотентно). |
| SUB-R12 | `--force` перебудовує наявний SRT. Якщо вміст не змінився — файл не чіпаємо. Інакше попередню версію зберігаємо як `subtitles.<YYYYmmdd-HHMMSS>.srt.bak` поруч (його могли редагувати вручну). |
| SUB-R13 | `--dry-run` нічого не пише, а для кожної задачі показує: створити / оновити / без змін, кількість титрів було → стане, кількість «щільних». |
| SUB-R14 | Команда ніколи не звертається до YouTube і не змінює статус задачі. Для задач з `video_id` — попередження, що доріжку на YouTube не оновлено. Нові відео отримують новий SRT через звичайний `upload`. |
| SUB-R15 | Задача без транскрипту пропускається з повідомленням; невідомий id → код виходу 1. |

## 5. Нефункціональні вимоги

Чиста функція без нових залежностей; лінійна складність за кількістю слів. Годинний транскрипт
(~10 000 слів) обробляється за < 1 с.

## 6. Інтерфейси

Конфіг, секція `transcribe:` (поруч з наявними `max_chars`, `max_lines`):

```yaml
transcribe:
  max_cue_seconds: 7.0   # 2.0–15.0
  min_cue_seconds: 1.0   # 0.3–3.0, менше за max_cue_seconds
  max_cps: 17            # 8–30 символів за секунду
```

Файли: `workspace/<slug>/subtitles.srt` — формат без змін; резервні копії `subtitles.<час>.srt.bak`.

CLI:

```
audiotube subtitles [id ...] [--force] [--dry-run]
```

## 7. Критерії приймання

| ID | Given / When / Then | Тест |
|----|---------------------|------|
| SUB-AC1 | **Given** сегмент 0–20 с з текстом на 2 рядки **When** build_cues **Then** ≥ 3 титри, кожен ≤ 7 с, разом покривають 0–20 с | новий |
| SUB-AC2 | **Given** сегмент з двома реченнями, що разом не вміщаються в один титр **Then** межа титру — після крапки, а не посеред речення | новий |
| SUB-AC3 | **Given** фраза без розділових знаків **Then** розрив між словами, рядки збалансовані (різниця ≤ довжини найкоротшого слова розриву) | новий |
| SUB-AC4 | **Given** щільний титр і 2 с тиші після нього **Then** кінець подовжено так, що cps ≤ 17, але не далі за наступний титр | новий |
| SUB-AC5 | **Given** щільний титр без тиші після нього **Then** титр не змінено, лічильник «щільних» = 1 | новий |
| SUB-AC6 | **Given** пауза 0.2 с між титрами **Then** попередній закінчується там, де починається наступний; пауза 1 с — лишається | новий |
| SUB-AC7 | Властивості для довільних транскриптів: порядок, без накладань, рядки ≤ `max_chars`, ≤ `max_lines`, тривалість у межах `min…max` (крім випадку накладання з SUB-R2) | новий (генерація випадкових сегментів із фіксованим seed) |
| SUB-AC8 | Двічі той самий вхід → однаковий SRT | новий |
| SUB-AC9 | Наявні тести субтитрів (`test_transcript.py::CueTests`, PIPE-AC1, PIPE-AC6) проходять без змін | наявні |
| SUB-AC10 | **Given** задача з транскриптом без SRT **When** `subtitles` **Then** SRT створено; повторний запуск нічого не змінює | новий |
| SUB-AC11 | **Given** SRT за старими правилами **When** `subtitles --force` **Then** файл оновлено, стара версія в `.bak`; повторний `--force` — без змін і без нового `.bak` | новий |
| SUB-AC12 | `subtitles --force --dry-run` не змінює файлів і БД, показує «було → стане» | новий |
| SUB-AC13 | **Given** задача з `video_id` **When** `subtitles --force` **Then** SRT оновлено, YouTube не викликано (Publisher замокано й перевірено), статус і `captions_id` без змін, є попередження | новий |
| SUB-AC14 | **Given** задача без транскрипту і невідомий id **Then** перша пропущена з повідомленням, для другої код 1 | новий |

## 8. Відповідність конституції

I — детермінований код без LLM; III — однаковий вхід дає однаковий SRT (SUB-R8); IV — наявні `subtitles.srt`
перезаписуються лише через `--force` і з резервною копією (SUB-R12); VI — `--dry-run`, квоту YouTube не витрачаємо; VII — чиста функція, тести без Whisper/FFmpeg;
VIII — без нових залежностей; IX — повідомлення журналу українською.
