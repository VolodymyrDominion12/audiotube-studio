# 010 · Публікація завантаженого відео (`audiotube publish`)

**Статус:** implemented · **Версія:** 1.0 · **Дата:** 2026-11-23
**Залежить від:** 003 · **Модулі:** `youtube.py`, `cli.py`

## 1. Проблема

Конвеєр завантажує відео приватним (`youtube.default_privacy: private`) і на цьому зупиняється:
статус `done` означає «на каналі», а не «доступне глядачам». Щоб зробити відео публічним або
непублічним, автор досі мав або відкривати YouTube Studio, або писати ad-hoc скрипт на
`videos.update` — з ризиком затерти інші поля `status` (ліцензію, `embeddable`, позначку
AI-контенту) і без списання квоти. Це особливо незручно для демона: кожне відео потребує
ручної дії після публікації.

## 2. User stories

- **US1** Як автор, я хочу однією командою зробити завантажене відео публічним або непублічним.
- **US2** Як автор, я хочу бачити, що саме зміниться, перш ніж це станеться (`--dry-run`).
- **US3** Як автор, я не хочу втратити позначку AI-контенту й інші налаштування відео під час зміни приватності.
- **US4** Як автор, я хочу, щоб квота списувалась так само, як для решти дій з YouTube.

## 3. Поза межами

Зміна назви, опису, тегів чи категорії опублікованого відео; видалення відео (`videos.delete`);
відкладена публікація (`publish_at` уже працює на етапі `upload`, spec 003); автоматична
публікація з демона (окрема спека), кнопка у веб-UI.

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| PUB-R1 | `audiotube publish <id> [<id> ...] [--privacy public\|unlisted\|private] [--dry-run]` змінює приватність відео, прив'язаного до задачі (`jobs.video_id`). Типове значення `--privacy` — `public`. |
| PUB-R2 | Перед зміною читається поточний `status` відео, і новий ресурс зберігає `license`, `embeddable`, `publicStatsViewable`, `selfDeclaredMadeForKids`; `containsSyntheticMedia` береться з `youtube.contains_synthetic_media`. Відкладений `publishAt` не переноситься — ручна публікація його скасовує. |
| PUB-R3 | Квота: читання статусу — 1 одиниця, `videos.update` — 50 одиниць (`COST_READ` / `COST_WRITE`). Якщо квоти не вистачає, жодного виклику API не відбувається. |
| PUB-R4 | `--dry-run` не звертається до YouTube і не списує квоту; для кожної задачі показує `video_id` і цільову приватність. |
| PUB-R5 | Задача без `video_id` пропускається з повідомленням «спершу upload»; невідомий id — «задачу не знайдено». Якщо жодної задачі не лишилось — код виходу 1. |
| PUB-R6 | Після успіху друкується `https://youtu.be/<video_id>` і фактична приватність. Помилка API для одного відео не зупиняє решту; код виходу 1, якщо була хоч одна помилка. |
| PUB-R7 | Статус задачі не змінюється (`done` лишається `done`): публікація — це дія над відео, а не крок конвеєра. |
| PUB-R8 | Команда не чіпає локальні файли й YAML-метадані; повторний виклик з тією ж приватністю ідемпотентний (той самий результат, ті самі 51 одиниця квоти). |

## 5. Нефункціональні вимоги

Без нових залежностей і без мережі в тестах: YouTube-сервіс підмінюється фейком. Один виклик
`videos.update` на відео; порядок обробки — як передано в аргументах.

## 6. Інтерфейси

CLI: `publish`. Нового конфігу не потрібно; використовуються `youtube.contains_synthetic_media`
і наявний `QuotaTracker`.

```
$ audiotube publish 185 --privacy public
[185] Планування та архітектура в програмуванні: public → https://youtu.be/rUnptYKipPo
квота сьогодні: 2 102 / 10 000
```

## 8. Відповідність конституції

VI — приватність змінюється лише явною командою, `containsSyntheticMedia` зберігається;
VII — YouTube у тестах замінено фейком; VIII — токени не друкуються, лише `video_id` і URL.

## 9. Відомі ризики

Для проєктів без аудиту YouTube може відхилити `public` на рівні API (403) — команда це
покаже й лишить відео приватним. Квота на добу невелика, тож масова зміна приватності
(наприклад, 4 відео поспіль) з'їдає 204 одиниці — це дешево порівняно з завантаженням.
