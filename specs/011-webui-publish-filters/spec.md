# 011 · Веб-інтерфейс: публікація, лічильники, фільтри

**Статус:** implemented · **Версія:** 1.0 · **Дата:** 2026-11-23
**Залежить від:** 003, 008, 010 · **Модулі:** `webui.py`

## 1. Проблема

`audiotube web` дає чергу задач і кнопки кроків, але не відповідає на три щоденні питання:
«скільки аудіо взагалі лежить в `inbox/` і скільки з них ще не в черзі», «що вже на YouTube і
що готове до публікації», «як зробити відео публічним». Публікація (spec 010) у UI відсутня,
лічильників немає, а без фільтра серед 196 задач неможливо знайти потрібну.

## 2. User stories

- **US1** Як автор, я хочу бачити зведення: скільки задач, скільки на кожному статусі, скільки вже на YouTube.
- **US2** Як автор, я хочу знати, скільки аудіо лежить у `inbox/` поза чергою (забув `scan`).
- **US3** Як автор, я хочу змінювати приватність відео з інтерфейсу, без командного рядка.
- **US4** Як автор, я хочу фільтрувати чергу за статусом і шукати за назвою чи іменем файлу.

## 3. Поза межами

Автентифікація і віддалений доступ (сервер слухає лише `127.0.0.1`); редагування метаданих
кількох задач одразу; drag-and-drop завантаження файлів у браузері; окремий React-застосунок.

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| WEB2-R1 | `POST /api/jobs/<id>/publish?privacy=public\|unlisted\|private` змінює приватність відео через `Publisher.set_privacy` (spec 010) і повертає журнал із посиланням. |
| WEB2-R2 | Задача без `video_id` → HTTP 400 з повідомленням «спершу upload»; некоректне значення `privacy` → HTTP 400; жодного виклику YouTube. |
| WEB2-R3 | `GET /api/state` додає `counts`: `total`, `by_status` (усі шість статусів, нулі включно), `published` (є `video_id`), `ready_to_publish` (статус `rendered`). |
| WEB2-R4 | `GET /api/state` додає `files`: `inbox_audio` (усі аудіофайли в `inbox/` рекурсивно), `inbox_unregistered` (з них без задачі), `output_videos` (`*.mp4` у `output/`). `*.part` і приховані файли не рахуються. |
| WEB2-R5 | Головна сторінка показує рядок лічильників (задачі, опубліковано, готується, файли в inbox поза чергою, mp4 у output) і фільтри: пошук за назвою/файлом та вибір статусу. Фільтри працюють на клієнті, без запитів до сервера. |
| WEB2-R6 | Для задачі з `video_id` картка показує вибір приватності й кнопку «Змінити приватність»; кнопка «Опублікувати» (upload) показується лише коли `video_id` ще немає. |
| WEB2-R7 | Помилки дій повертаються як HTTP 400 з текстом і не валять сервер; стан після дії перечитується. |

## 5. Нефункціональні вимоги

Без нових залежностей (stdlib `http.server`, ванільний JS). `state()` не робить мережевих викликів:
лічильники файлів — це обхід `inbox/` і `output/`, тобто O(кількість файлів). Сторінка
оновлюється кожні 15 с, як і раніше.

## 6. Інтерфейси

```
GET  /api/state                    → {jobs, quota, config, counts, files}
POST /api/jobs/<id>/publish?privacy=public
```

## 8. Відповідність конституції

VI — публікація лише явною дією користувача; VII — YouTube у тестах замінено фейком;
IX — інтерфейс локальний, без зовнішніх залежностей і збірки.

## 9. Відомі ризики

Приватність не зберігається в базі (її знає лише YouTube), тому UI не показує поточний стан
відео — лише цільовий. Для 200+ задач повний `state()` щоразу серіалізує весь список; це
помітно лише на дуже повільному диску.
