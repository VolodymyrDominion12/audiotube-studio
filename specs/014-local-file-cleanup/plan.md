# 014 · План реалізації

**Спека:** [spec.md](spec.md) (approved разом із запитом користувача 2026-11-26)

## 1. Підхід

Локальне видалення — окремий прапорець `artifacts.audio_deleted`, а не новий `state`: стан
артефакту описує, чи є переказ у NotebookLM, і не має залежати від того, що лежить на диску.
`sync._one` перевіряє прапорець **до** будь-якої логіки `repair`/`--force`, тому повторне
завантаження неможливе без явної дії «Відновити».

Відео видаляємо без нового поля: `jobs.video=NULL` — це вже наявний стан «локального файлу
немає» (так робить демон після публікації), а `video_id` і `uploads` лишаються історією YouTube.

Альтернативу «видалити рядок артефакту» відкинуто: втрачається `sha256`/`bytes`/`downloaded_at`
і синк сприйме переказ як новий.

## 2. Зміни по модулях

| Модуль | Зміна | Вимоги |
|--------|-------|--------|
| `audiotube/db.py` | міграція `artifacts.audio_deleted`; `set_audio_deleted`, `audio_deleted_job_ids`; `save_artifact` скидає прапорець; `notebook_stats`/`notebook_items` віддають стан аудіо | FILE-R2, R4, R9 |
| `audiotube/sync.py` | `SyncReport.deleted`; пропуск артефактів із прапорцем (у т.ч. dry-run і `--force`); `report_json`/CLI-звіт | FILE-R3, R8 |
| `audiotube/webui.py` | дії `delete_audio`/`delete_video`/`restore_audio`; перевірка шляхів; поля `job_json` і `files`; кнопки, розміри, підтвердження; колонка «видалено» на `/notebooks` | FILE-R1, R2, R5–R7, R9, R10 |
| `audiotube/daemon.py` | не брати незавершені задачі з видаленим аудіо; відрендерені — брати | FILE-R8 |
| `audiotube/cli.py` | `_process` пропускає задачі з видаленим аудіо; звіт `sync` показує `deleted` | FILE-R3, R8 |

## 3. Дані

- `ALTER TABLE artifacts ADD COLUMN audio_deleted INTEGER NOT NULL DEFAULT 0` (міграція для
  наявних баз, у `_SCHEMA` — одразу).
- Нових ключів `config.yaml` немає.
- Файли: `inbox/<ноутбук>/<файл>.m4a` + `*.part` (аудіо); `output/<slug>.mp4`,
  `output/<slug>_preview.mp4` (відео). YAML, транскрипти, субтитри й `*.jpg` не чіпаємо.

## 4. Ризики й відкат

- **Гонка з синком/демоном** (окремий процес): видалений файл може бути скачаний ще раз, поки
  синк уже почав завантаження. Прапорець у БД від цього не губиться, наступний синк пропустить.
- **Шлях поза керованою текою** — жорстка відмова (400) до будь-якого `unlink`.
- **Помилка `unlink`** — прапорець не ставимо, повертаємо помилку; файл лишається.
- Відкат: прибрати кнопки/маршрути; колонка `audio_deleted` безпечна для старих версій
  (ігнорується), а `jobs.video=NULL` — уже штатний стан після `daemon` cleanup.
