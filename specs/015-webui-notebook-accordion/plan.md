# 015 · План реалізації

**Спека:** [spec.md](spec.md)

## 1. Підхід

Замінюємо таблицю ноутбуків на акордеон усередині `NOTEBOOKS_HTML`. Список, як і раніше,
береться з `GET /api/notebooks`; перекази — з наявного `GET /api/notebooks/<id>` лише в момент
першого розгортання. Жодних змін у БД чи API.

Стан сторінки:

- `notebooks` — масив із `/api/notebooks`;
- `openId` — відкритий ноутбук (не більше одного);
- `itemCache` — `Map<id, payload>` на час життя сторінки;
- `query`, `filter` — клієнтські пошук і фільтр.

Розгортання: `openNotebook(id)` згортає попередній, ставить `openId`, розгортає рядок,
оновлює URL через `history.pushState` і викликає `ensureItems(id)`. Згортання — `closeNotebook()`
з `pushState('/notebooks')`. `popstate` читає `location.pathname` і синхронізує `openId` без
нового запису в історію.

Відкинута альтернатива — серверний рендер акордеона: дублював би форматування лічильників і
ускладнював оновлення після синку, не даючи нічого для 97 рядків.

Відкинута альтернатива — кілька відкритих ноутбуків одночасно: користувач явно просив, щоб
решта згорталася, а один відкритий тримає сторінку компактною.

## 3. Дані

Міграцій немає. Використовуються наявні `notebook_stats()` і `notebook_items()`.

## 4. Ризики й відкат

- **Втрата deep link** — `/notebooks/<id>` лишається маршрутом і відкриває акордеон; перевіряємо
  тестом `test_notebooks_deep_link_and_history`.
- **Історія браузера** — кожне розгортання/згортання додає запис; `popstate` обробляє повернення.
  Якщо це заважатиме, достатньо замінити `pushState` на `replaceState` в одній функції.
- **Кеш після синку** — `runSync` викликає `refresh({force: true})`, який чистить `itemCache`.
- Відкат: повернути попередній `NOTEBOOKS_HTML` з git; API і БД не змінюються.
