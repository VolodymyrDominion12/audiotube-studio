# 016 · Публікація через справжній браузер

**Статус:** implemented · **Версія:** 1.0 · **Дата:** 2026-11-28
**Залежить від:** 003 (метадані, `uploads`), 010 (публікація) · **Модулі:** `browser_publish.py`, `cli.py`, `webui.py`, `config.py`
**Детальний дизайн:** [plan.md](plan.md)

## 1. Проблема

Data API потребує OAuth-клієнта, квоти й аудиту проєкту: неаудитований застосунок не може
публікувати `public`, а квота 10 000 од./добу обмежує кількість відео. Частина авторів уже
має звичайний акаунт YouTube і хотіла б публікувати так само, як це робить людина у
YouTube Studio — руками в браузері, без API-ключа, квоти й OAuth-застосунку.

## 2. User stories

- **US1** Як автор без OAuth-застосунку, я хочу один раз увійти в Google у вікні, яке
  відкриває програма, щоб далі публікувати без пароля й без Data API.
- **US2** Як автор, я хочу, щоб відео, назва, опис, теги, приватність, обкладинка й
  субтитри додавались у Studio автоматично — так само, як це робив би я вручну.
- **US3** Як обережний автор, я хочу мати режим, де бот заповнює все, але фінальну кнопку
  «Опублікувати» натискаю я сам.
- **US4** Як автор, я не хочу випадково опублікувати те саме відео двічі або зламати
  API-публікацію, яка вже працює.

## 3. Поза межами

- Публікація без нагляду людини (демон, systemd, cron) — браузерний режим лише інтерактивний.
- Обхід перевірок YouTube, капчі, 2FA, «браузер небезпечний» — вхід виконує людина.
- Відкладена публікація (`publish_at`) через UI Studio: у браузерному режимі не підтримується,
  відео публікується зі звичайною приватністю, у журнал пишеться попередження.
- Плейлисти через UI: не чіпаємо (`manage_playlists` стосується лише API-режиму).
- Мультиканальні акаунти: обирається канал, на який залогінено профіль; перемикання каналу —
  вручну в браузері.
- Публікація Shorts, прямих ефірів, спільнотних дописів.

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| BROW-R1 | `audiotube browser-auth` МУСИТЬ відкрити справжній Chrome із виділеним профілем `youtube.browser.profile_dir` (типово `data/browser/youtube`) **без CDP-підключення** — щоб Google не блокував вхід, — дати людині увійти в Google, дочекатися закриття вікна й зберегти сесію на диску. Пароль програма не читає й не зберігає. |
| BROW-R2 | `audiotube browser-upload [ids]` МУСИТЬ завантажувати відео через UI YouTube Studio: файл, назва, опис із footer, обкладинка (одразу на кроці деталей під час створення відео, очікуючи прикріплення прихованого `input[type=file]`), теги, приватність, «не для дітей», позначка зміненого/синтетичного контенту (якщо Studio її пропонує), субтитри. Data API не викликається. |
| BROW-R3 | Сесія зберігається між запусками: якщо в профілі вже є вхід, браузер не показує форму логіна, а `browser-upload` одразу переходить до Studio. |
| BROW-R4 | Якщо входу немає, а режим неінтерактивний, команда МУСИТЬ завершитись помилкою з інструкцією `audiotube browser-auth`, не намагаючись вгадувати пароль. |
| BROW-R5 | Після успішної публікації задача отримує `video_id`, статус `uploaded`, запис у `uploads`, далі `done`; `quota` не списується. |
| BROW-R6 | Задача в статусі `done` повторно не публікується. Задача в `uploaded` з `video_id` догружає лише обкладинку/субтитри, але не відео. |
| BROW-R7 | `--dry-run` МУСИТЬ перевірити доступ до Studio, показати план (назва, приватність, теги, файли) і скриншот діалогу, **не вибираючи файл**, щоб не починати завантаження й не створювати чернетку; БД не змінюється. |
| BROW-R8 | `--review` МУСИТЬ заповнити все (включно з обкладинкою), дочекатися 100% завантаження й зупинитися на кроці публікації; після натискання людиною «Опублікувати»/«Зберегти» і закриття діалогу програма знаходить `video_id` у «Вміст» Studio й завершує задачу. Час очікування — `youtube.browser.publish_timeout`. |
| BROW-R9 | Приватність береться з `meta.privacy` або `youtube.default_privacy` (типово `private`); `publish_at` ігнорується з попередженням. |
| BROW-R10 | Обкладинка й субтитри — best-effort: якщо UI Studio змінився, у журнал пишеться попередження, а публікація відео не вважається невдалою. Якщо обкладинку не вдалося поставити в діалозі створення, програма пробує поставити її на сторінці `/edit`. |
| BROW-R11 | `video_id` МУСИТЬ братися з рядка «Вміст» Studio за назвою (посилання в діалозі до публікації — це ще чернетка). Якщо відео не знайдено — помилка без повторної публікації. |
| BROW-R12 | Кожна помилка UI МУСИТЬ супроводжуватись скриншотом у `data/browser/screenshots/` із зазначенням шляху в повідомленні (з обмеженим таймаутом скриншота, щоб не зависати при збої). |
| BROW-R13 | Веб-UI МУСИТЬ мати кнопку «Через браузер» для відрендереної задачі; запуск іде у фоні, стан і журнал доступні через `GET /api/browser`, при відкритті сторінки активний прогін підхоплюється автоматично, одночасно працює лише один браузерний прогін. |
| BROW-R14 | Браузерний режим не змінює поведінку API-публікації (`upload`, демон, `auto_upload`); це окремі команди й окрема кнопка. |
| BROW-R15 | Залежність від Playwright імпортується ліниво: без неї решта програми працює, а браузерні команди дають зрозумілу помилку. |

## 5. Нефункціональні вимоги

- Один браузерний прогін на процес; повторний запуск під час роботи — помилка «вже працює».
- Профіль, скриншоти й логи — під `data/` (у `.gitignore`), права 0700 на каталог профілю.
- Селектори Studio локалезалежні: пошук за `name`/`id`/структурою, текстові фолбеки — українською
  та англійською.
- Жодних запитів до YouTube Data API: у браузерному модулі немає імпорту `googleapiclient`.
- Час очікування елементів — `youtube.browser.timeout` (60 с), логін — `login_timeout` (900 с).
- Цикли очікування в UI (завантаження, кнопки «Далі»/«Опублікувати», збереження) МУСЯТЬ
  перериватися з помилкою, якщо сторінку/вікно браузера закрито.

## 6. Інтерфейси

```
audiotube browser-auth [--keep-open]
audiotube browser-upload [ids...] [--review] [--dry-run] [--keep-open]
```

`config.yaml`:

```yaml
youtube:
  browser:
    profile_dir: data/browser/youtube   # окремий профіль Chrome, не ваш основний
    chrome: null                        # шлях до Chrome; null = автопошук
    login_timeout: 900                  # секунд на ручний вхід
    timeout: 60                         # секунд на один елемент UI
    publish_timeout: 1800               # секунд очікування в --review
    keep_open: false                    # не закривати вікно після роботи
```

Файли: `data/browser/youtube/` (профіль), `data/browser/screenshots/*.png`.
HTTP: `POST /api/jobs/<id>/browser-upload?review=1`, `GET /api/browser`.

## 8. Відповідність конституції

- **I** — це детермінований етап конвеєра: фіксована послідовність кроків UI, без LLM.
- **II** — стан у SQLite: `video_id`, статуси, `uploads`; після падіння прогін продовжується з `uploaded`.
- **III** — `done` не публікується вдруге, повторний `finish` ідемпотентний.
- **IV** — профіль і скриншоти не перезаписують чужі файли; відео лишається на місці.
- **V** — неофіційний UI YouTube ізольований у `browser_publish.py`; решта коду залежить від протоколу `StudioDriver`.
- **VI** — типово `private`, AI-позначка вмикається, є `--dry-run` і `--review`; пароль не зберігається.
- **VII** — тести без мережі й без браузера: драйвер підмінюється фейком.
- **VIII** — усе локально, секретів у репозиторії немає (профіль у `data/`).
- **IX** — повідомлення й документація українською.
